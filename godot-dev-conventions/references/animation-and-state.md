# 动画与状态切换约定

## 核心目标

避免动画切换把节点状态带歪，让动画驱动逻辑时仍然保持状态边界清晰。

## `AnimationPlayer` 切换禁忌

切换动画前，不要使用 `animation_player.frame = 0` 作为“重置”手段。

原因：

- 这样会把动画位置强行回到开头。
- 同时会把各条 track 的状态回退到该时刻的键值。
- 如果新动画没有覆盖某条 track，旧动画该时刻残留的值可能继续生效。

## 默认做法

- 直接切换到目标动画，让新动画自然接管。
- 不要在切换前先 `stop()` 再硬重置帧。
- 如果确实需要统一重置状态，优先使用专门的 `RESET` 动画并显式推进一次。

```gdscript
animation_player.play("RESET")
animation_player.advance(0)
animation_player.play("idle")
```

## 动画与逻辑的边界

- 动画可以驱动节奏点和演出点。
- 玩法真状态不要完全隐含在动画播放过程里。
- 对外部系统重要的状态，仍应保留脚本侧可读状态或明确事件。

## 状态切换建议

- 先定义允许的状态边界，再决定动画如何映射这些状态。
- 简单对象可用清晰的状态变量。
- 状态明显增多、转移复杂时，再引入更完整的状态组织方式。

## 反模式

- 把“是否能攻击/是否能受击/是否结束前摇”完全寄托在多个分散动画 track 的副作用上。
- 为了修一个动画串台问题，在多个调用点都加一次额外重置。
- 动画、碰撞、受击、移动状态互相隐式覆盖，缺少单一状态入口。
