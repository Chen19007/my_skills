# 表格协作

把表格作为用户与助手共同维护的事项清单：用户逐项填写意见，助手按编号处理、补充证据并回写进展，之后继续验收。重点是让用户容易找到要看的内容、填写反馈和追踪处理结果。

## 选择入口与范围

- 先找当前任务已经使用的协作表；用户给了表格或要求继续处理时，读取最新文件再操作。不要另建一份同名用途的平行真源。
- 用户提到音效表、动作表等参考时，先检查其实际列、状态、反馈记录和链接，再借鉴有效部分。新任务是否独立成表，按审核对象与维护周期判断；不直接改造参考表。
- 只在任务范围确实不清楚时询问。已明确要全量核查时，保留无需调整的事项并说明原因，不只列出建议修改项。
- 默认生成可编辑的本地 `.xlsx`。沿用用户指定的格式、存放位置或在线表格；不因“协作”一词自动上传、分享或联系他人。
- 表格读写使用当前可用的表格能力；存在适用的专用技能时遵循其工具与验证约定。本技能不规定具体库或文件格式内部操作方法。

## 新建协作清单

采用一个主清单，加上实际需要的历史记录。新表通常用“事项清单”和“反馈记录”两页；小清单也可在同一页保存历史。已有表用历史列、独立页或其他方式记录反馈时，沿用其有效结构。

主清单按“可独立讨论和验收的一项”建行，推荐字段如下；按任务裁剪，不为凑齐字段制造空列。

| 字段 | 用途 |
|---|---|
| 固定编号 | 跨排序、筛选及多轮处理定位同一事项 |
| 对象／事项 | 用户能认出的角色、素材、功能或场景；必要时附技术标识 |
| 当前情况 | 已核实的行为、版本或当前接入内容 |
| 建议／待确认问题 | 尚未确认的方案及其理由，与当前事实分开 |
| 处理状态 | 本项目前处在哪一步 |
| 最新反馈（填写） | 用户填写意见的主要位置，保持易找、易读 |
| 下一步 | 一项具体可执行动作，说明由助手处理还是等待用户判断 |
| 预览／试听／证据入口 | 对应当前版本的真实文件、页面或验证结果 |
| 处理记录 | 简述已经做了什么、结果及仍未完成的部分 |

- 编号一经使用不随行号变化，不因重排重编号；拆分事项时新增编号，保留原项及关联。
- 条件、章节或版本差异影响验收结论时分行。确实共享同一处理项时，用编号关联，避免复制多个可编辑的结论。
- 建议值、推断与未验证信息明确标注。不要把聊天里的建议填成已采用配置，不根据外观猜测行为，不编造数量、预览或通过记录。
- 当前情况与证据应符合项目来源规则，并记录可追溯的版本／日期或位置。旧预览可以保留，但标明历史版本；缺少新预览时写“待补充”。

## 状态与验收

新表可采用以下默认状态；已有状态含义清楚时继续沿用，不强行迁移。

| 状态 | 使用条件 |
|---|---|
| 待核实 | 关键事实或证据不足，尚不能下结论 |
| 待讨论 | 已提出建议，等待用户决定方案 |
| 待调整 | 调整方向已确定，尚未完成实施 |
| 待验收 | 已完成调整，等待用户试用、试听或审阅；必要时可命名为“待试玩” |
| 已确认 | 用户已明确认可该项当前版本，或已满足用户事先明确授权的客观验收条件 |
| 暂不调整 | 用户明确决定暂缓或保留现状；记录理由及未解决问题 |

- 自动检查通过可以写入处理记录，不能据此推断用户认可主观效果。
- 助手建议“不调整”不等于用户已确认。未经确认先标待讨论，证据不足则待核实。
- 新反馈推翻原结论时，归档原确认的版本与意见，再回到适当状态，不能继续显示旧的已确认结论。
- 技术检查未完成、存在阻塞或只做了部分修改时如实说明，不能只用一个绿色状态掩盖缺项。

## 读取反馈并处理一轮

1. 重新读取当前表格，按固定编号核对最新反馈、状态和原记录。保留用户措辞；不把历史意见当作本轮新指令。
2. 将用户意见与助手建议区分。明确修改意见可在现有授权范围内执行；仅询问、比较或讨论时先回答，不自动改业务内容。要求建表本身不授权实施表内所有建议、提交代码或发布。
3. 处理有明确依据的事项，记录实际修改与验证结果。若一条反馈影响多项，列明关联编号及理由；遇到会改变用户意图的分歧，先确认该决策，并继续不依赖它的事项。
4. 将已处理的反馈原文追加到历史，推荐记录“事项编号、反馈日期／轮次、原文、处理内容、结果、证据”。来源未提供日期时，不反推原反馈日期；可记录本轮归档日期并标明含义。
5. 更新对应行的状态、下一步和处理记录。未处理或仅部分处理的意见仍留在最新反馈区；只有原文已完整归档且处理完毕时，才可清空该单元格。
6. 重复读取同一轮时，依据原有处理记录识别已处理内容，避免重复实施或重复追加历史。用户再次提出相同意见时，作为新反馈保留，不能只因文字相同忽略。

## 增量更新与文件保护

- 导入最新表格做定点更新，不从旧生成数据重建已填写的工作簿。保留非目标行、用户文字、旧记录、有效公式、链接、页签和既有功能。
- 更新前保留可恢复副本或可用版本，并记录本轮目标编号。写回前确认源表未被其他操作修改；发生冲突时重新读取并核对目标单元格，不覆盖较新的用户反馈。
- 本地文件优先先导出到临时文件，验证后替换。若文件被占用，保留已验证的候选文件并告知用户，不反复强行覆盖。在线表格采用其原生版本与精确区域更新能力。
- 后续只维护一份明确的当前协作表；备份、预览和验证记录按项目约定归档，不让多个“最新版”并存而无说明。

## 显示与验证

- 把对象、状态、最新反馈和下一步放在容易看到的位置；较长的技术依据靠后。使用筛选、冻结关键列／表头、换行与适当列宽；用文字状态配合颜色，不只靠颜色区分。
- 突出用户填写区域。统计只在有助于协作时添加，并随数据或状态更新；不要为简单清单增加仪表盘或重复页签。
- 保存后重新打开最终文件，检查目标行变更、非目标数据与历史保留、编号唯一、关联编号和链接有效；有公式时检查重算与错误值。
- 新表或布局变化应预览代表区域，确认长反馈可读、列标题完整。无法做视觉验证时明确说明，不把封装检查写成显示效果已确认。
- 返回当前表格入口，以及本轮处理范围、待用户看的项和阻塞。避免在回复里再复制整张清单，产生另一份难以同步的版本。
